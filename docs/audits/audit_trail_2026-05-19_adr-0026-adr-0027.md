## Residual risk

- **Empirical-before-amendment rule** (ADR-0027 §D-3) has no automated enforcement — operator self-discipline only. A future ADR could codify behavioral claims without empirical decomposition; the only catch is the audit-remediate-loop's literature-check branch (which DID catch the Phase O.10 Hsu-Kuan inversion + the Phase O.11 R1 AFML §13.2 misattribution + the Phase O.14 R1 AFML Ch. 7 misattribution + walk-forward set overreach). The empirical-before-amendment rule operates at the meta layer; its enforcement is via the same audit-remediate-loop machinery.
- **Substrate-vintage 16-char prefix** for `promising-*` annotations may collide if the project adopts many substrates within a short window (low probability with current 4-SHA inventory but not zero).
- **The 1000-cell cap derivation** is provisional pending `P1-ADR-0027-CELL-BUDGET-CAP-EMPIRICAL-CALIBRATION` — the v1 number may be off by 2-7×. Soft cap with operator-tunable override mitigates.
- **The §0 Component 3 forward-bootstrap mandate** creates a retroactive-cascade workload (re-running pre-2026-05-18 KPI cards' walk-forwards) tracked under `P1-ADR-0026-V3-KPI-RERUN-FOR-COMPONENT-3`. Wall-clock-significant; sequenced per operator priority.
- **`dsr_activation_size`-vs-`M>1`** threshold is now aligned to the existing project convention but the convention itself (currently 10) is pending empirical calibration per `P1-DSR-ACTIVATION-SIZE-EMPIRICAL-CALIBRATION`.
- **Genetic-successor §D-4 discipline** depends on §17 revision-log discipline which is currently uneven across hypotheses (H062 + H065 are well-documented; H050 + H053 less so). New successor pre-registrations from ADR-0027-adoption forward will satisfy §D-4 by construction; retroactive enforcement on existing hypotheses is informal.
